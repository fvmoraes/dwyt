All -% columns are percent reductions. INPUT, TOOL, OUT and COST are
relative to the baseline arm. MEM-% is relative to dwyt_v4, because the
baseline consults no project memory at all: it reports n/a rather than a
flattering 100%. COST-% uses the ranker's cost-model ratios, including expected
recovery overhead, not currency.
NOT MEASURED by this harness:
  - completion_rate
      requires a live agent loop; a synthetic harness cannot observe whether a
      task succeeded
  - cost_per_successfully_completed_task
      requires observed provider usage and a priced model; deriving it from
      fixtures would fabricate the spec's north-star metric
  - cache_hit_rate
      only real when the provider reports it; DWYT never claims an unobserved
      cache hit
  - latency
      no request is issued, so there is nothing to time
claim_allowed: false
The context, memory and tool-output reductions reported here are measured and
reproducible. They are NOT a product savings claim: completion rate, real cost
and cache hit rate are unmeasured here, and spec §69 requires evidence that
completion did not regress before any percentage is published.
